## 1. 类型安全自检
- 无 `any`（除非有 TSDoc 注释说明原因）；不确定类型用 `unknown`。
- 所有公共函数/方法有显式返回值类型标注。
## 2. 回归与副作用检测
- **函数签名兼容**：修改后的函数/接口 signature 与所有调用方兼容，不得静默破坏上游。
- **Zustand Store shape**：Store 的 state 字段增删，需检查所有 `useStore(state => state.xxx)` 引用是否仍然有效。
## 3. 代码质量
- **函数过长**:单个函数超过100行，且无强耦合逻辑，无明确的理由
- **命名不规范**：变量或函数命名中性化，无明确业务含义。 
  - 必须遵循**typescript**命名规范
- **鲁棒性**：无边界检查，核心逻辑无异常处理，catch 代码块必须写入error级别日志，并记录明确的输入、错误信息
- **代码重复**：违反DRY原则
## 4. 日志规范
- **框架统一**: 后端代码日志统一使用 `logger` 模块(`src/utils/logger.ts`),禁止显示使用 `console.log()`
- **日志级别**: 根据日志重要程度使用不同级别（`debug`, `info`, `warn`, `error`）。核心业务流程至少使用 `info` 级别日志，异常必须使用 `error` 级别。
- **日志内容**: 日志必须包含足够的上下文信息（如 `sessionId`, `userId`, 关键输入参数等），以便于问题排查,异常类型日志必须包含错误堆栈信息
## 5. 配置安全
- 代码禁止直接编码如：api key，账密相关等敏感信息，必须从配置文件中获取变量后使用
- 如果是key，认证相关如果缺失配置，则引用配置需要断言，如果失败在记录日志并抛出异常
## 6. 避免代码坏味道
1. 如在函数中使用 import 
2. 函数体行数超过100行，且无强耦合逻辑，无明确的理由，则基于抽取方法`重构`技巧优化
3. 过多if else特别是嵌套if else, 嵌套循环，且无强耦合逻辑，无明确的理由
4. 嵌套3目运算
